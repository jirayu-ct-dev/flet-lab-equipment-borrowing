# ขอบเขตระบบยืม–คืนอุปกรณ์

สถานะ: ขอบเขตที่อนุมัติสำหรับ MVP

เอกสารนี้สรุปขอบเขตเพื่อใช้อ้างอิงระหว่างพัฒนา โดยรายละเอียดเชิงออกแบบอยู่ใน [system-plan.md](system-plan.md) และลำดับงาน/เกณฑ์ตรวจรับอยู่ใน [implementation-plan.md](implementation-plan.md)

## เป้าหมายและข้อจำกัดทางเทคนิค

- ระบบยืม–คืนอุปกรณ์ของสาขาวิทยาการคอมพิวเตอร์ ที่ใช้งานง่ายและมีขั้นตอนน้อย
- ใช้ Python + Flet แบบ Web และ SQLite เท่านั้น
- เป็นโปรเจกต์ในวิชา: ไม่ออกแบบสำหรับ production scale, multi-tenant หรือ distributed system
- โครงสร้างข้อมูลแยกข้อมูลหลักออกจากธุรกรรม เพื่อให้เปลี่ยนชื่อคณะ สาขา หรือชนิดอุปกรณ์ได้โดยไม่ผูกแกนระบบกับห้องแล็บโดยตรง

## ผู้ใช้งานและสิทธิ์

มีเพียง 2 actor

| Actor | ทำได้ |
| --- | --- |
| Admin | จัดการผู้ใช้ ข้อมูลหลัก อุปกรณ์ การยืม–คืน ประวัติ และ import ผู้ใช้ |
| ผู้ยืม | ดูข้อมูลและประวัติของตนเอง ดูอุปกรณ์พร้อมยืม เปลี่ยนรหัสผ่าน และจัดการการเชื่อม LINE |

ผู้ยืมครอบคลุมนักศึกษา อาจารย์ และเจ้าหน้าที่ แต่ใช้สิทธิ์การยืมชุดเดียวกันใน MVP ผู้ยืมไม่มีสิทธิ์สร้าง อนุมัติ แก้ไข ยกเลิก หรือจองรายการยืมเอง

## บัญชีและข้อมูลผู้ใช้

- ใช้ username 3–50 ตัวอักษร: อังกฤษ ตัวเลข `.`, `_`, `-`; ไม่ซ้ำโดยไม่สนตัวพิมพ์ใหญ่–เล็ก
- เก็บชื่อ–นามสกุล, อีเมลสำรอง, บทบาท, ประเภทผู้ใช้ และสถานะบัญชี
- นักศึกษาต้องมีคณะ สาขา รุ่น และหมู่เรียนเมื่อรุ่นมีมากกว่าหนึ่งหมู่; อาจารย์/เจ้าหน้าที่ต้องมีคณะและสาขา
- Admin สร้างหรือ import ผู้ใช้ได้; import รองรับ CSV และ XLSX พร้อม template, preview, แถวผิดพลาด และป้องกัน username ซ้ำ
- รหัสผ่านเริ่มต้นของผู้ใช้ที่สร้างใหม่เท่ากับ username และบังคับเปลี่ยนเมื่อเข้าใช้ครั้งแรก; เก็บเฉพาะ password hash
- ฐานข้อมูลใหม่สร้าง Admin ครั้งแรกเพียงครั้งเดียว: `admin` / `admin1234` และบังคับเปลี่ยนรหัสผ่านทันที
- Admin รีเซ็ตรหัสผ่านได้; อีเมลเป็นข้อมูลสำรอง ไม่ใช่ช่องทางส่งอีเมลอัตโนมัติ
- ใช้การปิดใช้งานแทนการลบบัญชีที่มีประวัติ

## ข้อมูลหลักและอุปกรณ์

- Admin จัดการคณะ, สาขา, รุ่น, หมู่เรียน และหมวดหมู่อุปกรณ์ได้
- แยกชนิดอุปกรณ์ (ชื่อ, หมวดหมู่, ยี่ห้อ, รุ่น, รายละเอียด) จากอุปกรณ์รายชิ้น
- อุปกรณ์รายชิ้นมี asset code ที่ไม่ซ้ำ, ตำแหน่งจัดเก็บ และสถานะพร้อมยืม/ถูกยืม/ปิดใช้งาน
- ข้อมูลหลัก ชนิดอุปกรณ์ และอุปกรณ์ที่มีประวัติแล้วใช้การปิดใช้งานแทนการลบ

## การยืมและคืน

- Admin เป็นผู้สร้างรายการยืมเท่านั้น และเลือกอุปกรณ์พร้อมยืมได้หลายชิ้นในรายการเดียว
- ระบุผู้ยืม วันยืม และวันครบกำหนด; วันครบกำหนดห้ามก่อนวันยืม
- ห้ามใส่อุปกรณ์ซ้ำในรายการ, ห้ามยืมอุปกรณ์ inactive/ถูกยืม, และผู้ใช้ inactive หรือผู้เกินกำหนดยืมเพิ่มไม่ได้
- บันทึกรายการยืมและเปลี่ยนสถานะอุปกรณ์แบบ transaction เดียว: ถ้าชิ้นใดใช้ไม่ได้ รายการทั้งหมดต้องไม่ถูกสร้าง
- คืนได้บางส่วน โดยเก็บวันคืนแยกตามอุปกรณ์รายชิ้น; รายการจะปิดเมื่อคืนครบทุกชิ้น
- ไม่มีการจำกัดจำนวนชิ้นตามประเภทผู้ยืมใน MVP

## หน้าจอและประสบการณ์ใช้งาน

### Admin

- Dashboard: กำลังยืม, เกินกำหนด, ครบกำหนดวันนี้, คืนวันนี้ และอุปกรณ์พร้อมยืม
- ยืม–คืน: ค้นหาผู้ยืม เลือกหลายอุปกรณ์ กำหนดวันครบกำหนด และยืนยันในหน้าทำงานเดียว
- ผู้ใช้: สร้าง/แก้ไข/ปิดใช้งาน/reset รหัสผ่าน/import และดูประวัติรายบุคคล
- อุปกรณ์: ชนิดอุปกรณ์ อุปกรณ์รายชิ้น และสถานะ
- ข้อมูลหลัก, ประวัติการยืม–คืน และบัญชี

### ผู้ยืม

- Dashboard และรายการที่กำลังยืมของตน
- อุปกรณ์พร้อมยืมพร้อมค้นหา
- ประวัติของตนเองเท่านั้น
- บัญชี: เปลี่ยนรหัสผ่าน ดูสถานะ LINE และยกเลิกการเชื่อม LINE

งานยืม–คืนต้องจบสั้นที่สุด ใช้ search เป็นหลัก ใช้ dropdown เฉพาะชุดข้อมูลที่ชัดเจน มี confirmation ก่อนเปลี่ยนข้อมูลสำคัญ และแสดงสถานะด้วยข้อความร่วมกับสีเสมอ

## LINE Login และ LINE Official Account

- ใช้ LINE Login สำหรับเข้าสู่ระบบ และ LINE Official Account/Messaging API สำหรับแจ้งเตือน โดยอยู่ Provider เดียวกัน
- ข้อมูลผู้ใช้หลักยังอยู่ในระบบ; LINE เก็บเฉพาะ LINE User ID ที่จำเป็นต่อการ login และ push message
- LINE หนึ่งบัญชีผูกกับผู้ใช้หนึ่งคนเท่านั้น; ผู้ที่ login LINE ครั้งแรกต้องยืนยัน username/password ของระบบก่อนผูก
- ผู้ใช้ยกเลิกการเชื่อมได้โดยบัญชีระบบยังใช้งานต่อด้วย username/password
- ผู้ใช้ต้องเพิ่ม Official Account เป็นเพื่อนจึงจะรับ push message ได้
- แจ้งข้อความธรรมดาเมื่อ: ยืมสำเร็จ, ก่อนครบกำหนด 3 วัน, ก่อนครบกำหนด 1 วัน, และคืนครบทั้งรายการ
- Reminder ใช้ Asia/Bangkok, ทำงานตอนเปิดระบบและวันละครั้งขณะ process ทำงาน, ป้องกันส่งซ้ำด้วยเวลาแจ้งบนรายการยืม
- การส่ง LINE เป็น best effort: ส่งไม่สำเร็จต้องไม่ rollback การยืมหรือคืน และไม่มี notification log หรือ retry queue

## สิ่งที่อยู่นอกขอบเขต

- คำขอยืม, การจอง, การต่ออายุ และ workflow อนุมัติหลายขั้น
- บันทึกสภาพ, ชำรุด, สูญหาย, ค่าปรับ, การชำระเงิน และ audit log
- การคำนวณวันหยุด หรือกฎการยืมแยกตามประเภทผู้ใช้
- Flex Message, อีเมลอัตโนมัติ, แอปมือถือแยก และฮาร์ดแวร์เฉพาะ
- Custom field, custom workflow, database abstraction, PostgreSQL/Docker และ multi-tenant เต็มรูปแบบ
- Production deployment, horizontal scaling, distributed scheduler และการส่ง reminder ย้อนหลังเมื่อระบบปิด

## เกณฑ์สำเร็จ

- Admin จัดการข้อมูล ผู้ใช้ อุปกรณ์ และยืม–คืนได้โดยไม่ต้องแก้ฐานข้อมูลเอง
- ผู้ยืมเห็นเฉพาะข้อมูลตนและอุปกรณ์พร้อมยืม
- ผู้ใช้ใหม่ข้ามการเปลี่ยนรหัสผ่านครั้งแรกไม่ได้
- อุปกรณ์รายชิ้นไม่ถูกยืมซ้อน และคืนบางส่วน/หลายชิ้นได้โดยสถานะถูกต้อง
- Import ระบุแถวที่ผิดพลาดและไม่สร้างข้อมูลซ้ำโดยไม่ตั้งใจ
- LINE ล้มเหลวไม่ทำให้ธุรกรรมยืม–คืนหายหรือย้อนกลับ และ reminder ไม่ส่งซ้ำ
