# เรื่องราวของระบบ — ระบบยืม-คืนครุภัณฑ์ BRU-CS

## 1. บริบท: สาขาวิทยาการคอมพิวเตอร์ มหาวิทยาลัยราชภัฏบุรีรัมย์

สาขาวิทยาการคอมพิวเตอร์ (BRU-CS) มีห้องปฏิบัติการหลายห้อง — ห้องปฏิบัติการ IoT,
ห้องคอมพิวเตอร์, ห้องหุ่นยนต์ — และมีครุภัณฑ์จำนวนมาก: บอร์ดไมโครคอนโทรลเลอร์,
เซ็นเซอร์ IoT, Raspberry Pi, กล้อง, หุ่นยนต์, โดรน, โน้ตบุ๊ก และอุปกรณ์ประกอบการเรียน

**เจ้าหน้าที่ของสาขา (แอดมิน)** เป็นผู้ดูแลระบบทั้งหมด: ลงทะเบียนครุภัณฑ์,
บันทึกรายการยืม-คืน, รับคืน และติดตามสถานะ ส่วน **อาจารย์และนักศึกษา** เป็นผู้ยืม —
ยืมไปใช้สอน, ทำโครงงาน, โปรเจกต์จบ, แข่งขัน และกิจกรรมของสาขา

## 2. ปัญหาเดิม (ก่อนมีระบบ)

- อุปกรณ์ IoT/เซ็นเซอร์เป็นชิ้นเล็ก ราคาไม่สูงแต่ **หายง่ายและมีจำนวนมาก** — นับรวมแล้วมูลค่าหลายแสนบาท
- การยืมใช้วิธี "บอกปากเปล่า" หรือจดในสมุด → ผ่านไป 2-3 สัปดาห์ **ไม่รู้ว่าใครถือของอยู่**
- ช่วงเปิดเทอม / ช่วงแข่งโครงงาน นักศึกษายืมพร้อมกัน → **ของชนกัน** รอของไม่เจอ
- เซ็นเซอร์/บอร์ดบางตัวถูกยืมไปแล้ว **ลืมคืนเป็นเดือน** ขวางการใช้ของรุ่นถัดไป
- ของหายไม่มีผู้รับผิดชอบ เจ้าหน้าที่คนเดียวคุมไม่ไหว
- เวลาตรวจครุภัณฑ์ประจำปี ไม่มีหลักฐานว่าของแต่ละชิ้นอยู่ที่ไหน ใครใช้ครั้งล่าสุด

## 3. ระบบเข้ามาแก้ปัญหาอย่างไร

| ปัญหา | ระบบแก้ด้วย |
|---|---|
| ไม่รู้ว่าใครถือของอยู่ | ครุภัณฑ์ทุกชิ้นมี **รหัสประจำตัว (asset code)** + สถานะ (พร้อมใช้/ถูกยืม/ส่งซ่อม/แจ้งหาย) |
| ยืมชนกัน | **ยืมต้องบันทึกผ่านระบบ** — ทุกคนเห็นสถานะ "ถูกยืม" ได้ทันทีจากหน้าอุปกรณ์ |
| ลืมคืน | ทุกรายการมี **วันครบกำหนดคืน** และผู้ยืมดูของตัวเองได้ผ่านหน้า "ของฉัน" (ล็อกอินด้วย LINE) |
| ของหาย | มี workflow **แจ้งหาย → ประเมินราคา → ชดเชย/ปิดเคส** พร้อมผู้รับผิดชอบชัดเจน |
| ของเสีย | คืนแล้วระบุ **ส่งซ่อมบำรุง** กักไว้จนกว่าจะบันทึกว่าซ่อมเสร็จ |
| ตรวจสอบย้อนหลัง | **ประวัติทุกการกระทำ** (ใครยืม ใครคืน ใครแก้ข้อมูล เมื่อไหร่) บันทึกถาวร |

## 4. ตัวละคร

| ชื่อ | สถานะ | บทบาทในระบบ | ตัวอย่างการยืม |
|---|---|---|---|
| กิตติพงศ์ | เจ้าหน้าที่สาขา | **admin** (จัดการครุภัณฑ์/คน/รายการทั้งหมด) | บันทึกยืม-คืน, รับคืน, ปิดเคสแจ้งหาย |
| อริสา | นักศึกษาชั้นปีที่ 3 | user | ยืม Raspberry Pi + เซ็นเซอร์ ทำโครงงาน IoT |
| ธนกฤต | อาจารย์ประจำสาขา | user | ยืมกล้อง depth สอนวิชา Computer Vision |
| ปวีณา | นักศึกษาชั้นปีที่ 4 | user | ยืม ESP32 + เซ็นเซอร์ ทำโปรเจกต์จบ |
| ศุภกร | นักศึกษาชั้นปีที่ 2 | user | ยืมกล้อง IP + โดรน เก็บภาพงานแข่งหุ่นยนต์ |
| ชลธิชา | อาจารย์ | user | ยืมคอมตั้งโต๊ะ + โปรเจกเตอร์สอนในชั้นเรียน |

## 5. สถานการณ์ตัวอย่าง (ใช้เล่าในการนำเสนอ)

1. **อริสา** (นศ.ปี 3) ยืม Raspberry Pi 5 + ชุดเซ็นเซอร์ ไปทำโครงงาน "โรงเพาะเห็ดอัตโนมัติ"
   → เจ้าหน้าที่กิตติพงศ์บันทึกในระบบ กำหนดคืน 5 วัน → สถานะขึ้น "ถูกยืม" ทันที
2. **ธนกฤต** (อาจารย์) จะยืม Raspberry Pi สอนแล็บ เห็นว่าถูกยืมอยู่
   → เลือกใช้ชุด Arduino แทน — ไม่ชนกัน ไม่ต้องเดินถาม
3. อริสาคืนชุดเซ็นเซอร์ก่อน (คืนบางส่วน) แล้วใช้บอร์ดต่อจนครบกำหนด → คืนครบ รายการปิด
4. **ปวีณา** (นศ.ปี 4) คืนบอร์ด ESP32 แต่ช่อง USB หลวม → บันทึก "ส่งซ่อม" กักไว้รอซ่อม
5. **ศุภกร** (นศ.ปี 2) แจ้งว่ากล้อง IP หายหลังงานแข่ง → แจ้งหายในระบบ → ประเมินราคา → บันทึกปิดเคส
6. สิ้นภาคการศึกษา **กิตติพงศ์** เปิดหน้าประวัติ: เห็นว่าครุภัณฑ์ทุกชิ้นถูกใช้กับวิชา/โครงงานไหนบ้าง
   → ใช้ตรวจครุภัณฑ์ประจำปี และวางแผนซื้ออุปกรณ์เพิ่ม

## 6. ผลลัพธ์ที่ใช้วัดความสำเร็จ (พูดในบทสรุป)

- ตามหาอุปกรณ์จาก "เดินถามทั้งสาขา" เหลือ "เปิดระบบดูใน 1 นาที"
- อุปกรณ์หาย/เสียมีผู้รับผิดชอบและหลักฐานครบ รองรับการตรวจครุภัณฑ์ประจำปี
- อาจารย์/นักศึกษาเห็นกำหนดคืนของตัวเองผ่าน LINE → อุปกรณ์ไม่ถูกกักเกินจำเป็น
- เจ้าหน้าที่คนเดียวบริหารครุภัณฑ์ทั้งสาขาได้อย่างเป็นระบบ
